# State Management Decision Tree

Руководство по выбору механизма хранения состояния в React-приложении.

---

## Дерево решений

```
Это данные с сервера (API)?
├── Да → React Query / RTK Query
└── Нет → клиентский стейт ↓

Нужен ли стейт только одному компоненту?
├── Да → useState / useReducer
└── Нет → нужен шаринг ↓

Насколько далеко компоненты в дереве?
├── Родитель → дети, 1–2 уровня → lift state up + пропсы
└── Глубже или сиблинги через общего родителя ↓

Сложность стейта и масштаб приложения?
├── Мало значений, небольшое приложение → Context
└── Много значений / сложные переходы / нужны DevTools → Redux
```

---

## 1. React Query / RTK Query — серверное состояние

**Когда использовать:**
- Данные приходят с API и нужно их кешировать
- Нужна инвалидация кеша после мутаций
- Нужен фоновый полинг или рефетч при фокусе окна

**Когда не использовать:**
- Для хранения UI-стейта (фильтры, флаги, открыт ли модал)
- Если данные не приходят с сервера

---

## 2. useState — локальный стейт

**Когда использовать:**
- Стейт нужен только одному компоненту
- Простое значение с одним-двумя переходами
- UI-стейт: открыт ли дропдаун, текущее значение инпута, флаг загрузки кнопки

**Когда не использовать:**
- Когда то же значение нужно читать в другом не дочернем компоненте (даже соседнем)

---

## 3. useReducer — локальный стейт со сложной логикой

**Когда использовать:**
- Несколько связанных значений, которые меняются вместе
- Много переходов между состояниями (например, форма с валидацией)
- Логика следующего состояния зависит от текущего

**Когда не использовать:**
- Для простых значений — `useState` проще и достаточно
- Когда стейт нужно шарить — `useReducer` сам по себе не решает задачу шаринга

---

## 4. Lift state up + пропсы

**Когда использовать:**
- Стейт нужен нескольким компонентам, но их общий родитель близко (1–2 уровня)
- Хочется избежать введения глобального механизма

**Когда не использовать:**
- Когда цепочка пропсов проходит через несколько промежуточных компонентов, которым эти данные не нужны (prop drilling)

---

## 5. Context — разделяемый стейт без лишних зависимостей

**Когда использовать:**
- Стейт нужен нескольким компонентам, но prop drilling неудобен
- Небольшое приложение или изолированная фича

**Когда не использовать:**
- Когда значений много и они меняются часто — нет встроенной мемоизации, все подписчики ре-рендерятся при любом изменении контекста

**Оптимизация при необходимости:**
- Разделить на несколько контекстов по зонам ответственности
- Использовать `memo` на компонентах-подписчиках

---

## 6. Redux — глобальный стейт

**Когда использовать:**
- Стейт нужен многим компонентам на разных уровнях дерева
- Нужна отладка через Redux DevTools (history actions, time-travel)
- Нужен `preloadedState` в тестах
- RTK Query уже в стеке — Redux store и так присутствует

**Когда не использовать:**
- Для локального UI-стейта одного компонента
- Для серверных данных — RTK Query справляется лучше
- В небольшом приложении без сложного шаринга стейта

---

## 7. URL params — навигационный стейт

**Когда использовать:**
- Состояние должно сохраняться при рефреше страницы
- Состоянием можно поделиться через ссылку (фильтры, поиск, текущая вкладка)

**Когда не использовать:**
- Для приватного или сессионного стейта, который не должен быть виден в URL

---

## 8. localStorage / sessionStorage

**Когда использовать:**
- Стейт должен сохраняться между сессиями (`localStorage`) или вкладками (`sessionStorage`)
- Пользовательские настройки: тема, язык, предпочтения

**Когда не использовать:**
- Для чувствительных данных
- Как основной источник правды для UI — синхронизация с React-стейтом нетривиальна

---

## Итоговая таблица

| Механизм | Область | Когда использовать                             |
|---|---|------------------------------------------------|
| RTK Query / React Query | Серверные данные | Данные с API, кеш, мутации                     |
| `useState` | Локальный | Простой UI-стейт одного компонента             |
| `useReducer` | Локальный | Сложные переходы, несколько связанных значений |
| Lift state + пропсы | Локальный / shared | Шаринг на 1–2 уровня вверх                     |
| Context | Shared | Небольшой шаринг в изолированной фиче          |
| Redux | Глобальный | Сложный шаринг, DevTools                       |
| URL params | Навигационный | Персистентность, шаринг через ссылку           |
| localStorage | Персистентный | Настройки между сессиями                       |
